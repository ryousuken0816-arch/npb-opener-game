# godot/ — ゲーム本体（Godot 4.7）

Godot エディタで `godot/project.godot` を開いて実行（F5）。タイトル → 球団選択 → ハブ画面。

## 配色

- 球団カラーは `GameData.TEAM_COLORS`（[メイン, サブ]）。`UiTheme.team_palette(球団名)` で背景・パネル・見出し・順位表などの色を作る
- 背景は白寄りの明るい色（メインカラーを薄めたもの）。黒基調にはしない
- メニューボタンは参考画像にならってボタンごとに固定色（試合へ=赤、日程表=ピンク、采配=橙、新戦力=緑、記録室=黄、システム=紫）

## 質感と動き（docs/references/README.md「UI全体の質感アップ」）

- 画面ごとに StyleBoxFlat を作らず、`UiTheme.gloss()` / `card()` / `style_button()` / `style_toggle()` / `heading()` を使う。
  Theme（`UiTheme.build()`）の Button・Panel・タブ・Tree の見出し・スクロールバーは GlossBox になっている
- 本文（説明文・表の数字）は読みやすさ優先で縁取りなし。見出し・ボタン・日付・ランク文字は縁取り＋影
- 画面のルート（タイトル・ハブ）で `UiFx.install(self)` を呼ぶと、あとから作ったボタンにも動きが付く。
  独自に動きを持つボタン（ハブのメニュー）はメタ `no_fx` を付けて対象外にする
- 演出はテンポ重視で 0.1〜0.2 秒。スクショを撮るテストは 0.3 秒待ってから撮る（早送り中の画面は待たずに撮る）

## コントローラー操作（docs/references/README.md「コントローラー操作」）

- 十字キー／左スティックでフォーカス移動、Ⓐ決定、Ⓑ戻る（Esc と同じ）、LB/RB でタブ切り替え。PC の XInput（Xbox 互換）を想定
  - LB/RB：ハブ・日程表＝順位表のセ・パ、采配＝サブ画面を順に（選手一覧ではタブ）
  - 日程表：日付の列もフォーカスできる（Ⓐで目標日に選び、選んだ列でもう一度Ⓐで早送り）。早送り中はⒷで中止、フォーカスは「早送り中止」へ移り、終わったら元に戻る
- 画面を開いたら最初の項目にフォーカスする。作り直す画面（1軍登録・起用設定・日程表）は作り直したあとも同じ位置にフォーカスを戻す
- フォーカスは自動（位置関係）で決まる。自動だとずれる所だけ `focus_neighbor_*` を設定（日程表のスライダー行→日付の列）
- マウスを乗せたときだけ出ていたツールチップは、十字キーでフォーカスしたときにも出る（`UiInput`）
- 決定/戻るの入れ替え（Switch 配置）は `UiInput.SWAP_CONFIRM_CANCEL`（システム設定ができたらそちらへ）
- クラス名を型として使うテスト（`extends SceneTree`）は、オートロードより先にコンパイルされるため `UiTheme` に依存するクラス（NameTag など）を型に使えない（`GameData` が見つからずコンパイルエラー）。`has_method()` などで判定する。
  `LeagueRoster`・`PlayerDetail` も同じ（`var league: Variant = GameState.league`、`load("res://…/player_detail.gd").open(...)`）。一度コンパイルに失敗するとゲーム側からも使えなくなる（`Nonexistent function 'new'`）

## 選手詳細（`PlayerDetail`）

- 開き方：采配の一覧の名前札はⒶ／クリックですぐ開く。1軍登録・起用設定は札を選ぶ操作があるので、**選んでいる札をもう一度Ⓐ／クリック**
  （1軍登録は右の「詳細を見る」でも）。Ⓑは「選択の取り消し→画面を戻る」の順。選手一覧は行でⒶ（Enter）／クリック。どの名前札も右クリックで開く
- 十字キーの前後の並びは開いた画面の並び（采配の一覧＝1軍→2軍、1軍登録＝その画面の札の順、起用設定＝スタメン→控え、選手一覧＝その一覧の行の順）。
  省くと同じ球団の全選手（投手→野手）
- 史実の年度別成績は `GameData.player_page()`（`data/<能力値の年>/players.json`。5MB 前後なので初めて開いたときに1年分だけ読む）。
  **選手ページは npb.jp の今のページなので未来の年の成績も入っている**。ゲームの年より前の年だけを出す
- 今季の行はゲーム内の成績（`GameState.season`）。2年目以降は前年も史実の成績になる（ゲーム内の過去の成績を保存する仕組みができたら差し替える）
- 背番号は `GameData.uniform_numbers()`（rosters.json の `number`。今は 2026年だけ）。無ければ空欄
- 所属球団の推移は年度別成績の「所属球団」から作る（1軍に出場した年のみ）。今は無い球団（福岡ダイエー・大阪近鉄など）は灰色の札

## 能力値データの場所

`GameData` は次の順に `<年>_<pre|post>.json` を探す。

1. `res://data/ratings/`（書き出し用。未作成）
2. リポジトリ直下の `generated/ratings/`（エディタ実行時はこちらを直接読むのでコピー不要）

書き出し（エクスポート）する段階で 1 へのコピー手順を用意する。

## フェーズ進行（可変ボタン）

シーズンは**日単位**で進む。`GameState.day` は「今日」（まだ試合をしていない日）の通し日数（`Season.day_number`）で、
開幕日から始まり、1日進めるとその日の全カードをシミュレーションして翌日になる。

- 日程表の「1日進める」「1週間進める」「この日まで早送り」→ `GameState.start_fast_forward(目標日)`。`_process()` が
  `FAST_FORWARD_INTERVAL`（0.12秒）ごとに1日進め、目標日の試合が終わったら止まる。`stop_fast_forward()` で途中で止める
  （日程表を閉じたとき・ハブの「試合へ」を押したときも止まる）
- ハブの「試合へ」（`advance()`）は近道：今月の残り日程をまとめて行い、翌月1日へ（最終月ならシーズン終了へ）
- 月が替わると `GameState.month_started` を出す。SPEC の「月ごとの粒度」（故障・トレードイベント、育成コマンド）はここに挟む（未実装）
- シーズンの期間は開幕日〜最終試合日（2008年は3/20〜10/12）。日程データ（`data/<年>/schedule.json`）が無い年は
  4/1〜10/31 を試合なしで進む（`GameState.season` は null）

最終日を終えると オフ へ進み、ボタンは次のフェーズ名に切り替わる：

シーズン終了・表彰 → 現役ドラフト（2022年オフ以降のみ）→ FA・トレード・ポスティング → 契約更改 → 戦力外・引退 → ドラフト → 春季キャンプ（翌年） → 開幕

- 表彰に入ると当年の `post` 能力値、春季キャンプで翌年の `pre` 能力値に切り替える（ファイルがなければ現状維持）

## 所属の管理と年越し（`LeagueRoster`、docs/SPEC.md「決定事項：所属の管理と史実の出来事」）

誰がどの球団にいるかは `GameState.league.team_of`（選手ID → 球団）で持ち、年が変わっても引き継ぐ。
能力値ファイルは能力の値を引くためだけに使い、読み込むたびに `GameData.apply_roster()` で所属を上書きする
（`GameData.players_of()`・`teams()`・選手データの `team` はゲーム内の所属。史実の球団は `hist_team`。所属していない選手は `team` が空）。
`Season` は `GameData.rostered_players()` から作る。

- 開始時：開幕時点の能力値ファイルの球団。ただしその年の開幕後に史実でトレードされた選手は移籍前の球団から（能力値ファイルは1年分の在籍なので移籍後の球団になっていることがある）
- シーズン中：史実のトレード（`data/trades.json`）を日付どおりに毎日起こす（CPU球団どうしで、全員がまだ移籍元にいるときだけ。自球団が関わるものは起きない）。`Season.transfer()` で両球団の1軍を自動で組み直す
- オフ（`GameState._enter()`）：
  - FA・トレード・ポスティング：メジャー移籍（`data/mlb_moves.json` の `left_after` の年。自球団の選手もいったん退団し、画面で引き留めを試せる）、年内のトレード、
    来季の準備（来季の開幕時点のファイルを `peek_ratings()` で先読みし、引退・仮IDの付け替え・メジャーからの復帰・新加入・外国人市場の候補を決める）、メジャーからの復帰（史実の球団へ）、
    FA宣言（`league.open_fa()`）。締め切り（`GameState.fa_resolve()`。可変ボタンで次へ進むときも自動）で移籍先が決まる
  - 契約更改：年俸を更新（`Salary.renew`）
  - 戦力外・引退：来季のファイルにいない選手は引退（外国人は「退団」と記録）
  - ドラフト：新人（前年秋のドラフトで指名された選手）とその他の新加入を史実の球団へ（ドラフト画面ができたら差し替える）
  - 春季キャンプ：新しい年のファイルを読み、仮ID（`tmp:…`、1軍に出ていない選手）を本来のIDに付け替え、球団名の変更（横浜→DeNA、自球団も）
  - 開幕：開幕前日までのトレード、外国人市場を閉じる（残った候補は来日しない）
- 外国人市場：来季に来日する新外国人（外国人の判定は `RosterRules.is_foreign`）。オフの間は新戦力の画面で自球団が獲得できる。
  CPU球団は契約更改・戦力外・ドラフトで1人ずつ、春季キャンプで残りを、史実で獲得した人数ぶん評価の高い順に獲得する。
  評価と提示額は来季のシーズン後の能力値に誤差（`MARKET_NOISE`）を足した「不完全な未来視」（画面に出す能力は開幕時点のまま）
- 記録：`league.log`（`kind`：trade / trade_skipped / mlb_leave / mlb_return / retire / rookie / join / foreign_candidate / foreign_sign / foreign_unsigned / rename /
  fa_declare / fa_move / fa_stay / mlb_keep / mlb_keep_failed）。新戦力の「出来事」タブに出す
- オフの編成：`GameState.sim_team_of(球団)`（`my_team()`）はオフの間、今の所属から自動で組んだ `SimTeam` を返す（所属が変わるたびに作り直す）

### FA・ポスティング（`FreeAgency`、docs/SPEC.md「決定事項：FA・ポスティング」）

- `GameState.fa()`（FA・トレード・ポスティングの段階だけ。それ以外は null）・`fa_open()`（締め切り前）・`fa_offer(id, 年俸, 年数)`・`fa_cancel(id)`・`mlb_keep(id, 年俸, 年数)`・`fa_resolve()`
- 締め切り前は可変ボタンが「FA・移籍交渉」でハブは FA の画面を開く（`GameState.advance()` は締め切ってから次へ進むので、テストや早送りでは画面を通さなくてよい）
- 国内FA：資格は在籍 `DOMESTIC_FA_YEARS`（8）年・前回から `REFA_YEARS`（4）年・複数年契約中でない・外国人枠でない。宣言は能力・出場量・年齢・年俸の安さからの確率
- 入札：CPU球団は必要度（同じ種類＝先発/救援/野手で何人目に入るか）と能力で決める（宣言したときに決め、締め切りまで非公開。画面には「関心：n球団」と、自球団の提示が通りそうかの★）。
  選手は 年俸×年数の上乗せ×元の球団の上乗せ×相性 の高い球団へ。入札が無ければ宣言残留。決まった年俸は契約年数のあいだ据え置き（`league.contract_until`。契約更改で飛ばす）
- 自球団の提示は希望額の 0.7〜2倍（`BID_CAP` 10億円まで。予算上限ができたら差し替え）
- メジャー移籍の引き留め：自球団の選手だけ1回。成功率 `MLB_KEEP_MIN`〜`MLB_KEEP_MAX`（5〜20%）。テストでは `fa.force_roll` で乱数を固定できる。
  成功したら `league.kept_mlb` に入り、`GameData.set_kept_players()`（`_sync_roster()` から）がその年のファイルの `mlb_players`（無ければ引き留めたときのNPBの能力値）を選手として足す（`kept_from_mlb`）。
  来季のファイルにいなくても引退させない（mlb_last の年まで）。史実でNPBに戻ったら普通の選手に戻る（`begin_year`）

### 年俸（`Salary`）

- 開幕時点（2008年）・途中加入：市場価値 `BASE × exp(K × 実力z) × 出場量^1.4`（実力z・出場量は能力値の直近3年の加重から）に
  在籍年数の係数（1年目0.3→7年目1.0→以降少しずつ上がり最大1.4）を掛け、在籍年数に応じた下限と比べる。3億円を超えた分は伸びを抑え、6.5億円で頭打ち
- 新人：ドラフト順位×高校／大学・社会人の表（1位 1500万／高校1200万 … 育成 400万／300万）
- 外国人：市場価値×1.3（最低3000万円）
- 契約更改：今季のゲーム内成績（OPS・防御率）と能力値から目標額を出し、減額制限（1億円超40%・以下25%）と上げ幅（3倍かつ+1.5億円まで）の範囲で近づける
- 2008年開幕の分布（`roster_year_check`）：平均 約3,300万円・中央値 約1,500万円・1億円以上 約60人・最高 約3.8億円、
  出場の多い選手の中央値 約9,000万円（下位1/4 5,500万・上位1/4 1.5億）、球団の総額 17〜35億円

## 試合シミュレーション（`sim/`）

- 能力値は `z = (値 − 63) / 17`（`tools/README.md` のスケールの逆）に直し、各確率を「基準値のロジット＋係数×z」のシグモイドで出す
- 打席の流れ：死球 → 四球（選球眼×制球）→ 三振（ミート×奪三振）→ 本塁打（パワー・弾道×被弾抑制）→ 打球の質（ミート・パワー×総合力）→
  凡打球（内野の守備力でアウト/内野安打、アウトは失策判定、併殺）／鋭い当たり（外野の守備力で安打・長打を抑え、肩で進塁を阻止）
- 走塁は走力と外野の肩で一塁→三塁・二塁→本塁・二塁打で一塁→本塁と憤死を判定。盗塁は走力で企図、走力と捕手の肩で成否
- 試合に出るのは1軍（`SimTeam.active`）の選手だけ。代打は1軍の控えから
- 采配方針（`SimTeam.tactics`、−2〜+2。自球団は思考設定、CPUは0）：送りバントの頻度と対象、盗塁の企図率、先発を代える球数の目安が変わる（係数は `game_sim.gd` の `*_TACTIC_*`）
- 采配：投手の打順・打力の低い打者は無死一塁/二塁で送りバント、DHなしの終盤は投手に代打。先発は目安の球数（スタミナ）＋5球・5失点で交代、
  7〜9回の僅差リードはセットアッパー2人→抑えの順。リリーフは前日35球超・3連投になる日は休み
- 疲労：目安の球数を超えると15球ごとに z −0.45。先発は中5日以上あける6人ローテ
- 勝敗投手：最後に勝ち越したときの投手が勝利（先発は5回以上）、その走者の責任投手が敗戦。セーブ・ホールドは簡易判定
- 延長は12回まで（引き分けあり）。パ・リーグ主催試合（交流戦含む）はDH制

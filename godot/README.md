# godot/ — ゲーム本体（Godot 4.7）

Godot エディタで `godot/project.godot` を開いて実行（F5）。タイトル → 球団選択 → ハブ画面。

## 構成

| パス | 役割 |
|---|---|
| `autoload/game_data.gd` (`GameData`) | 能力値JSON・史実の日程（`load_schedule()`）の読み込み・球団別の選手一覧・球団略称・ランク色。`apply_roster()` でゲーム内の所属を能力値データの `team`/`league` に書き込む（史実の球団は `hist_team`）。来季のファイルの先読み（`peek_ratings()`・`set_supplement()`）、史実データの球団略称→正式名（`resolve_team()`）、ドラフト指名（`draft_entry()`） |
| `autoload/ui_input.gd` (`UiInput`) | コントローラー操作：LB/RB（キーボード Q/E・PageUp/PageDown）の `ui_tab_prev` / `ui_tab_next`、決定/戻るの入れ替え（`SWAP_CONFIRM_CANCEL`、Switch 配置用）、フォーカスしたときのツールチップ、フォーカスの補助（`focus_first` / `focus_index` / `focus_nth` / `grab`） |
| `autoload/game_state.gd` (`GameState`) | 年・今日の日付（`day`）・フェーズ・自球団と、その年のペナント（`season: Season`）。日単位の進行と早送り（`start_fast_forward()` / `stop_fast_forward()`）、可変ボタンの文言と進行（`advance()`＝1か月）。順位表は `standings()` |
| `sim/league_roster.gd` (`LeagueRoster`) | 所属の管理（`GameState.league`）：誰がどの球団にいるか・年俸・年越しの史実の出来事（トレード・メジャー移籍と復帰・引退・新人・外国人市場）と、その記録（`log`）。下記「所属の管理と年越し」 |
| `sim/free_agency.gd` (`FreeAgency`) | 1オフ分の FA・ポスティング（`league.fa`）：FA資格・宣言の確率、CPU球団の入札（必要度・能力）、自球団の提示・引き留め、締め切りで移籍先を決める（`resolve`）、メジャー移籍の引き留め（`keep_mlb`、成功率5〜20%）。下記「FA・ポスティング」 |
| `sim/contract_renewal.gd` (`ContractRenewal`) | 1オフ分の契約更改（`league.contracts`）：自球団の選手ごとの今季の年俸・査定額・提示額・調整できる範囲・据え置きの理由、締めたか（`resolved`）。球団ごとの予算上限 `BUDGET`（`budget(球団)`）。下記「契約更改」 |
| `sim/releases.gd` (`Releases`) | 1オフ分の戦力外・引退（`league.releases`）：史実の引退の一覧・CPU球団の戦力外・自球団の候補（残す価値の低い順）・育成・保護・戦力外の印、締めたか。下記「戦力外・引退」 |
| `sim/growth.gd` (`Growth`) | 成長・衰え・引退（史実の能力値ファイルが無い年。docs/AUTORUN.md 作業27）。係数は `generated/growth.json`（`tools/growth_coefficients.py`）。下記「成長・衰え・引退」 |
| `sim/foreign_players.gd` (`ForeignPlayers`) | 架空の外国人選手（史実の無い年の外国人市場の候補。docs/AUTORUN.md 作業31）。ひな形は `generated/foreign.json`（`tools/foreign_players.py`）。下記「架空の外国人選手」 |
| `sim/salary.gd` (`Salary`) | 年俸の計算（万円）：開幕時点・途中加入（能力値＋在籍年数）、新人（ドラフト順位）、外国人（提示額）、契約更改。係数は冒頭の定数 |
| `sim/trade.gd` (`Trade`) | トレード交渉の仕組み（docs/AUTORUN.md 作業8）。選手の価値＝能力からの市場価値（`Salary.ability`・`market_value`）×年齢の係数−年俸の半分、守備位置の需要（`Draft.NEED_SHARE` と比べた過不足）を掛け、相手が受け取る価値（自球団の選手＋金銭）÷出す価値 から成功率（0.85→0、1.5→1、★5段階）。条件の確認（片側3人・所属・FA宣言中・支配下70人）と成立（所属の入れ替え・出来事 trade）。時期の判定と申し込みは `GameState.trade_block_reason()`／`trade_request()`（シーズン中は7月31日まで、オフは FA・トレード・ポスティング〜春季キャンプ。契約更改・戦力外・ドラフトは締めてから）。断られた球団とは同じ日（オフは同じ段階）は交渉できない（`LeagueRoster.trade_refused`、セーブに入る） |
| `sim/fa_compensation.gd` (`FaCompensation`) | FA移籍の補償（docs/AUTORUN.md 作業18）。FAを締め切ると（`GameState.fa_resolve`）移籍1件ごとに、旧球団の日本人選手の年俸順位でランク（`rank_of`）を付けて補償を決める。年ごとのルールは `rule()`：〜2025年オフは A＝1〜3位・B＝4〜10位で「人的補償（獲得球団のプロテクト28人の外から1人）＋金銭（A 50%・B 40%）」か「金銭のみ（A 80%・B 60%）」、2026年オフは35歳以上は補償なし、2027年オフからは A＝1〜3位・B＝4〜8位で指名権（A＝2巡目・B＝3巡目、`LeagueRoster.draft_pick_comp` → `Draft.set_pick_moves`）か金銭（A 100%・B 80%）。外国人枠・育成・今オフにFAか人的補償で加わった選手はプロテクトの外にできない。CPU球団どうしはその場で決まり（プロテクトは `LeagueRoster.keep_score` の上位28人、旧球団はプロテクト外のいちばん価値の高い選手が `CPU_TAKE_VALUE` 以上なら獲る）、自球団が関わるものは画面で決める（可変ボタンで次へ進むとおまかせ）。出来事 `fa_comp` |
| `sim/season.gd` (`Season`) | 1年分のペナント。史実の日程の status=played の試合を日付順にシミュレーションし、全試合の結果（スコア・イニング別得点・勝敗セーブ投手・個人成績）と球団成績・個人通算成績を保持 |
| `sim/game_sim.gd` (`GameSim`) | 1試合のシミュレーション（打席単位、docs/SPEC.md の8段階）。係数は冒頭の定数 |
| `sim/sim_team.gd` (`SimTeam`) | 球団の編成：1軍登録（試合に出るのは1軍だけ）、スタメン・打順（DHあり/なし）と控え、先発6人ローテ・中継ぎ（先頭2人がセットアッパー）・抑え、采配方針（`tactics`）。投手の登板間隔。開幕時に自動編成（CPU球団はそのまま）、自球団は采配画面から書き換える |
| `sim/roster_rules.gd` (`RosterRules`) | 1軍登録の史実のルール：登録人数の上限（2008〜18年28人・2019年〜29人・2020〜21年31人）、外国人枠（4人・投手野手とも3人まで、2020〜21年は5人）、抹消後10日間の再登録不可、外国人の判定（ドラフト歴なし＋経歴あり、在籍8年以上は日本人扱い） |
| `scripts/user_settings.gd` (`UserSettings`) | ユーザーの設定（セーブとは別）。`user://settings.cfg`。`get_value`／`set_value`。フルスクリーン（`UiInput.set_fullscreen`・F11・Alt+Enter）が使う。`path` をテストで差し替える |

| `scenes/hub/save_view.gd` (`SaveView`) | セーブ／ロードの画面（ハブの「システム」、タイトルの「続きから」ではロードだけ）：セーブ／ロードの切り替え（LB/RB）、スロット1〜3とオートセーブの札（概要と保存日時）、上書き・ロードの確認（はい／いいえ） |

## 質感と動き（docs/references/README.md「UI全体の質感アップ」）

- 画面ごとに StyleBoxFlat を作らず、`UiTheme.gloss()` / `card()` / `style_button()` / `style_toggle()` / `heading()` を使う。
  Theme（`UiTheme.build()`）の Button・Panel・タブ・Tree の見出し・スクロールバーは GlossBox になっている
- 本文（説明文・表の数字）は読みやすさ優先で縁取りなし。見出し・ボタン・日付・ランク文字は縁取り＋影
- 画面のルート（タイトル・ハブ）で `UiFx.install(self)` を呼ぶと、あとから作ったボタンにも動きが付く。
  独自に動きを持つボタン（ハブのメニュー）はメタ `no_fx` を付けて対象外にする
- 演出はテンポ重視で 0.1〜0.2 秒。スクショを撮るテストは 0.3 秒待ってから撮る（早送り中の画面は待たずに撮る）

## 画面のはみ出し対策（docs/AUTORUN.md 作業11）

- 原因だった不具合：`UiFx.slide_in` は `position`（＝アンカーからの余白 `offset_*`）を動かすので、演出（0.16秒）の途中で開き直す・閉じると途中の位置が余白に残り、
  ハブは `offset_left`・`offset_top` しか置き直していなかったため、開く・閉じるをくり返すたびにサブ画面の右端が画面の外へずれていった。
  `UiFx.stop_slide()` で演出を止めてから、`hub.gd` の `_set_wide()` で四辺の余白をすべて置き直す
- 画面のルートのパネル（ハブの `SubScreen`、選手詳細の枠）は、中身を `UiTheme.fit_scroll()` の ScrollContainer（hub.tscn の `%Fit`）で包む。
  中身の最小の大きさが枠を超えてもパネルは広がらず、そのときだけスクロールバーが出る（収まっていれば見た目は同じ）。パネルの余白は包みの内側へ移すので、切り取るのはパネルの縁
- 長くなりうる1行の文言（メッセージ・見出し）は `UiTheme.fit_label()`（最小幅0・入りきらない分は「…」）。複数行でよい文言は `autowrap_mode`（1軍登録の右の要約など）
- 采配の各画面は幅 986（1280x720 で広げたとき）に収まるよう札・要約の幅を決めている。画面を足したら `tests/layout_fit_check.gd` に開く手順を足す

## スマホ表示（Web 版を iPhone などで開いたとき。2026-11-02）

- 判定は `UiLayout`（autoload/ui_layout.gd）。スマホのブラウザ（`web_ios`・`web_android`）か縦長のウィンドウならスマホ表示。タッチ画面付きのパソコンはパソコンのまま。
  スマホでは下の帯の「PC表示」でパソコンの表示にでき、右上の「📱 スマホ表示」で戻す
- 画面の論理サイズ：パソコン 1280x720（変えない）。スマホの縦は幅 480（iPhone の幅 390px で1px＝実寸約0.81px）、横は 1280x592（パソコンと同じ配置）。
  `UiLayout.touch_units()` が実寸44px（指で押しやすい大きさ）の論理ピクセル、`bottom_inset()` が下の操作の帯の高さ
- 画面ごとに書かずに全画面に効かせる調整は `scripts/touch_adapt.gd`（UiLayout の子。スマホのときだけ、ノードが足されるたびに画面を調べ直す）：
  ボタン・名前札・タブを実寸44px以上に／札を並べた Grid の列の数を幅に合わせる（縦で3列）／縦で幅に入らない横並びは入るだけの列で折り返す（左右のパネルは上下に）／
  表の行（幅を決めた値の欄・細い見出しが並ぶ行）はそのまま横スクロール／入れ子の一覧は中身の高さまで伸ばして画面ごと1つのスクロールに／縦の小さな文字（表の外）は15まで大きく／
  コントローラーの「◀ LB」「RB ▶」は隠す。指の操作：なぞってスクロール（ScrollContainer・Tree。ボタンの上から始めても）、長押し＝右クリック（名前札→選手詳細）、
  タップ・長押しでツールチップを出す。パソコン表示に戻すと元に戻す。調整したくないノードは `set_meta("touch_keep", true)`
- ハブの下の操作の帯 `MobileNavBar`（scenes/hub/mobile_nav_bar.gd、層60＝選手詳細より上）：「← 戻る」（選手詳細を閉じる／サブ画面の戻る）・日程表・采配・可変ボタン・PC表示。
  縦はボタンの上にパソコンの下の帯と同じ説明の1行。サブ画面・選手詳細・速報の帯はこの分だけ下を空ける。スマホではサブ画面の見出しの「戻る」は出さない
- 表の多い画面（ドラフト・作戦会議・FA・記録室・日程表・表彰・補償・契約更改・戦力外、選手詳細の成績・経歴）は、縦のとき「📱 横向きにすると見やすくなります」を出す（iOS の Safari は向きを固定できない）
- 画面を足したら `tests/mobile_fit_check.gd` にも開く手順を足す

## コントローラー操作（docs/references/README.md「コントローラー操作」）

- 十字キー／左スティックでフォーカス移動、Ⓐ決定、Ⓑ戻る（Esc と同じ）、LB/RB でタブ切り替え。PC の XInput（Xbox 互換）を想定
  - LB/RB：ハブ・日程表＝順位表のセ・パ、采配＝サブ画面を順に（選手一覧ではタブ）
  - 日程表：日付の列もフォーカスできる（Ⓐで目標日に選び、選んだ列でもう一度Ⓐで早送り）。早送り中はⒷで中止、フォーカスは「早送り中止」へ移り、終わったら元に戻る
- 画面を開いたら最初の項目にフォーカスする。作り直す画面（1軍登録・起用設定・日程表）は作り直したあとも同じ位置にフォーカスを戻す
- フォーカスは自動（位置関係）で決まる。自動だとずれる所だけ `focus_neighbor_*` を設定（日程表のスライダー行→日付の列）
- マウスを乗せたときだけ出ていたツールチップは、十字キーでフォーカスしたときにも出る（`UiInput`）
- 決定/戻るの入れ替え（Switch 配置）は `UiInput.SWAP_CONFIRM_CANCEL`（システム設定ができたらそちらへ）
- クラス名を型として使うテスト（`extends SceneTree`）は、オートロードより先にコンパイルされるため `UiTheme` に依存するクラス（NameTag など）を型に使えない（`GameData` が見つからずコンパイルエラー）。`has_method()` などで判定する。
  `LeagueRoster`・`PlayerDetail` も同じ（`var league: Variant = GameState.league`、`load("res://…/player_detail.gd").open(...)`）。一度コンパイルに失敗するとゲーム側からも使えなくなる（`Nonexistent function 'new'`）

## 選手詳細（`PlayerDetail`）

- 開き方：采配の一覧の名前札はⒶ／クリックですぐ開く。1軍登録・起用設定は札を選ぶ操作があるので、**選んでいる札をもう一度Ⓐ／クリック**
  （1軍登録は右の「詳細を見る」でも）。Ⓑは「選択の取り消し→画面を戻る」の順。選手一覧は行でⒶ（Enter）／クリック。どの名前札も右クリックで開く
- 十字キーの前後の並びは開いた画面の並び（采配の一覧＝1軍→2軍、1軍登録＝その画面の札の順、起用設定＝スタメン→控え、選手一覧＝その一覧の行の順）。
  省くと同じ球団の全選手（投手→野手）
- 史実の年度別成績は `GameData.player_page()`（`data/<能力値の年>/players.json`。5MB 前後なので初めて開いたときに1年分だけ読む）。
  **選手ページは npb.jp の今のページなので未来の年の成績も入っている**。ゲームの年より前の年だけを出す
- 今季の行はゲーム内の成績（`GameState.season`）。2年目以降は前年も史実の成績になる（ゲーム内の過去の成績を保存する仕組みができたら差し替える）
- 背番号は `GameData.uniform_numbers()`（rosters.json の `number`。今は 2026年だけ）。無ければ空欄
- 所属球団の推移は年度別成績の「所属球団」から作る（1軍に出場した年のみ）。今は無い球団（福岡ダイエー・大阪近鉄など）は灰色の札

## シーズン中に能力を史実へ寄せる（`SeasonBlend`、docs/AUTORUN.md 作業40）

- 史実のある年（`<年>_post` がその年の成績まで入っている年。2008〜2026年）は、開幕は `<年>_pre` の能力で始め、**月替わりごと**に
  リーグ全体の消化した試合の割合（× `SeasonBlend.SPEED`＝1.0）だけ `<年>_post` へ寄せる（`GameState._blend_ratings` → `GameData.set_season_blend`）
- 寄せるのは 打撃（ミート・パワー・選球眼・走力・弾道）・守備位置ごとの守備力と肩力・投球（総合・スタミナ・K/9・BB/9・HR/9・球速）。役割・特殊能力・detail は開幕のまま
- その年によく出た野手ほど post で上がる（野手だけ平均が上がって打高になる）ので、能力ごとの「出場量で重みを付けた post − pre の平均」（`league_shift`）を post から引いて寄せる。守備力・肩力・球速は引かない
- 能力値データ（`GameData.ratings` の選手）をその場で書き換えるので、選手詳細・記録室などはそのまま追従する。試合の選手（`SimPlayer`）は `Season.refresh_ratings` で読み直し、CPU 球団は1軍・スタメンを組み直す（自球団の編成は変えない）
- 混ぜる前の値は `GameData._blend_base` に写してあり、能力値ファイルを読み直すと（`load_ratings`）開幕時点に戻る。シーズン後（表彰）は今までどおり `<年>_post` を読み直す
- セーブには割合（`season_blend`）だけを入れ、ロードで pre を読んでから同じ割合で混ぜ直す
- 史実の無い年（2027年〜）は寄せない（成長・衰えの仕組み）
- 確認：`godot/tests/season_blend_check.gd`（ヘッドレス約3分半。2026年、佐藤輝明が 開幕 → 7月 → 9月 → シーズン後 と上がる・試合の能力・選手詳細・セーブ／ロード・ゲーム内の成績の順位（乱数でぶれるので6シーズンの平均。OPS 3.7位・本塁打 4.0位））

## 調子と故障（`Health`、docs/AUTORUN.md 作業45）

- `GameState.health`（`sim/health.gd`）が全球団の選手の調子と故障を持つ。シーズン中、毎日の試合の前（`_health_before_games`：治った選手を戻す・調子を動かす）と後（`_health_after_games`：故障の判定）に動く。年をまたいで持ち、セーブに入る（`health`）
- **調子**：絶不調〜絶好調の5段階（-2〜2）。3〜21日ごとに1段階ずつ動き、普通へ戻りやすい（`FORM_TOWARD`・`FORM_STAY`）。試合では打者のミート・パワー・選球眼と、投手の奪三振・制球・被弾・総合の z 値を `FORM_Z`（0.12）×段階だけ上下させる（`GameSim`）。両チームの打者を絶好調・投手を絶不調にすると得点が約1.3倍
- **故障**：野手は1試合出るごと `P_FIELDER_GAME`、投手は投げた球数ごと `P_PITCHER_PITCH`（110球を超えた分は2.5倍）、試合に出ない日は練習で `P_PRACTICE_DAY`。年齢で 0.75〜1.6倍。部位ごとに全治の日数（`PARTS_FIELDER`・`PARTS_PITCHER`）があり、最後の25%（最低3日）は「2軍で調整中」。どちらの間も1軍の試合には出られず、1軍に上げられない
  - 規模の目安（2008年を1年）：1球団 4〜15人・平均 約10人、平均の全治 約30日、60日以上の長期離脱がリーグで5〜7人
  - **CPU球団**：故障したら `SimTeam.swap_out_injured`（抹消して2軍の同じ位置に合う選手を上げる）。治ったら `return_from_injury` で控えのいちばん劣る選手と入れ替えて元の持ち場（スタメンの打順・守備位置、先発・抑え）に戻す（抹消から10日たっていなければ翌日以降に `Health.returning` で試し直す）。`auto_register` は1回 0.25秒かかるので使わない
  - **自球団**：1軍に残ったまま（試合では `SimTeam.game_lineup`・`game_bench` で控えが代わりに出る。先発・救援も故障者を飛ばす）。ハブの球団の札の下（`HubStatusCard`）と1軍登録の画面の上に知らせ、「故障者を入れ替える」でまとめて入れ替えられる（`GameState.swap_out_injured`）
- **ニュース**（種類 `injury`）：自球団の1軍の選手の故障（主力＝スタメン・先発ローテの5人・抑え・勝ちパターンは速報）と復帰、CPU球団の主力の全治30日以上の離脱は速報。早送りを止める種類は自球団の分が「自球団の速報」、他球団の分が新しい「他球団の長期離脱」（`injury`。「すべて」に入る。「大事なものだけ」には入れていない）
- **表示**：名前札（`NameTag`）の右上に調子の矢印（↑↗→↘↓・赤〜青の丸）、故障中は左上に赤い「故」、調整中は橙の「調」（シーズン中の、調子を追っている選手だけ）。1軍登録の要約に調子と故障、選手詳細の今季成績の見出しに調子と故障、「登録」に「故障 あと◯日」
- 確認：`godot/tests/health_check.gd`（ヘッドレス約1分半）。スクショ：`tests/health_capture.gd`

## フェーズ進行（可変ボタン）

シーズンは**日単位**で進む。`GameState.day` は「今日」（まだ試合をしていない日）の通し日数（`Season.day_number`）で、
開幕日から始まり、1日進めるとその日の全カードをシミュレーションして翌日になる。

- 日程表の「1日進める」「1週間進める」「この日まで早送り」→ `GameState.start_fast_forward(目標日)`。`_process()` が
  `FAST_FORWARD_INTERVAL`（0.12秒）ごとに1日進め、目標日の試合が終わったら止まる。`stop_fast_forward()` で途中で止める
  （日程表を閉じたとき・ハブの「試合へ」を押したときも止まる）
- ハブの「試合へ」（`advance()`）は近道：今月の残り日程をまとめて行い、翌月1日へ（最終月ならシーズン終了へ）
- 月が替わると `GameState.month_started` を出す。SPEC の「月ごとの粒度」（故障・トレードイベント、育成コマンド）はここに挟む（未実装）
- シーズンの期間は開幕日〜最終試合日（2008年は3/20〜10/12）。日程データ（`data/<年>/schedule.json`）が無い年は
  4/1〜10/31 を試合なしで進む（`GameState.season` は null）

最終日を終えると ポストシーズン（CS・日本シリーズ）、日本一のあと オフ へ進み、ボタンは次のフェーズ名に切り替わる：

ポストシーズン → シーズン終了・表彰 → 現役ドラフト（2022年オフ以降のみ）→ FA・トレード・ポスティング → 契約更改 → 戦力外・引退 → ドラフト → 春季キャンプ（翌年） → 開幕

- 表彰に入ると当年の `post` 能力値、春季キャンプで翌年の `pre` 能力値に切り替える（ファイルがなければ現状維持）

## ポストシーズン（`Postseason`、docs/AUTORUN.md 作業23）

- 段階 `GameState.Phase.POSTSEASON`（セーブに番号が入るので enum の最後に足した。並びは `next_phase()`：公式戦 → ポストシーズン → 表彰）。日程データの無い年は公式戦から表彰へ直接
- 公式戦の最終日を終えると `_start_postseason()` が最終順位で組み合わせと日程を作り、`day` を初戦の日へ。日単位で進む（`is_daily_phase()`。日付の表示・早送り・采配の編成は公式戦と同じ）。
  試合は `Season.teams`（SimTeam）をそのまま使い、個人成績は `Postseason.batting/pitching` に別に持つ（公式戦の成績・順位は変わらない）
- 形式（`Postseason.STAGES`）：ファースト（2位対3位、2位の本拠地、3試合・2勝）→ ファイナル（1位の本拠地、6試合・4勝、1位にアドバンテージ1勝）→ 日本シリーズ（7試合・4勝、
  偶数年はセ・奇数年はパが第1・2・6・7戦を主催、引き分けで決まらなければ第8戦以降）。勝ち数が並んで試合が尽きたら上位が勝ち抜け。
  2020年はセがCSなし・パが1位対2位の4試合・3勝（`NO_CS`・`SHORT_CS`）。球場は主催球団の今季の主催試合で最も多い球場
- 日程は公式戦の最終日から：ファースト＋3日、ファイナル＋7日、日本シリーズ＋19日（第1・2戦→移動日→第3〜5戦→移動日→第6・7戦）
- 進め方：可変ボタン（ポストシーズン中は「試合へ」）・日程表でポストシーズンの画面を開く。`GameState.postseason_play_round()`＝今の段階を最後まで
  （自球団が勝ち残っていなければ日本一まで）、`postseason_play_all()`＝日本一まで、画面の「次の試合へ」「この段階を最後まで」は `start_fast_forward()`（1日ずつ）。
  `advance()` はポストシーズン中は `postseason_play_round()`、日本一のあとは表彰へ
- **`advance_through(日, stop_at_postseason=false)`** は最終日を越えるとポストシーズンも全部行って表彰まで進む（テスト・「すぐドラフトへ」用）。ハブの「試合へ」は `true` でポストシーズンの入口で止まる
- 日本一が決まると `GameState.postseason_history[年]`（`Postseason.summary()`：両リーグの優勝・CSの勝者・日本一・相手・成績・各シリーズの勝者とMVP）に残り、
  記録室の「チーム成績の推移」（金色＝日本一、下に歴代の優勝・日本一）に出る。`GameState.postseason` は翌年の開幕まで残る（セーブにも入る）
- 優勝争い：公式戦の後半は毎日 `Postseason.pennant_race()` で首位のマジック（他球団が全勝しても届かなくなるのに要る首位の勝ち数。直接対決は考えない）を調べ、
  点灯（最初の値・日付）と優勝決定（日付・球団）を `GameState.pennant_race` に1回ずつ記録する。今のマジックは `pennant_status(リーグ)`
- 演出：`GameState.celebrate(kind, 球団, 見出し)`。自球団のリーグ優勝（早送りも止める）と日本一（どの球団でも）。ハブが `Celebration` を重ねる。自動処理（`skip_to_phase`）の途中は出さない

## 大事なニュースで早送りを止める（docs/AUTORUN.md 作業35）

## ドラフトの読み上げ（`DraftVoice`、docs/AUTORUN.md 作業28）

ドラフトの画面は、1位の入札（1球団ずつ）・抽選（3D）・外れ1位・2位以降・育成の指名を、中継風の札（`PickAnnounce`）で1つずつ発表し、
「第1巡選択希望選手、千葉ロッテ、鈴木泰成、投手、青山学院大学」の決まった言い回しで読み上げる。
発表は時間が来ると次へ（読み上げが終わるまで待つ）。Ⓐ／クリックで名前をすぐ出す → もう一度で次へ。Ⓑ（「発表を飛ばす」）で待っている発表を消し、
ウェーバーの途中なら自球団の番まで他球団の発表をしない。札の下の「早送り」で短く（読み上げなし）、「発表：ゆっくり／ふつう／速め／自球団だけ」、
「読み上げ：オン／オフ」、「音量」は `user://settings.cfg` に残る。自球団の指名は長めでチャイムが鳴る。テストでは音を出さない。

**OS の音声合成を使うため `project.godot` に `audio/general/text_to_speech=true` を入れている**（エディタでプロジェクト設定を保存し直すと消えることがあるので、消えたら「オーディオ → 一般 → Text to Speech」をオンに）。

声の差し替え（自分の PC で用意した声を差し込む口。**声のデータ・モデルはリポジトリに入れない**。`.gitignore` に `voice/`・`*.vvm`・`*.onnx`）：
`user://settings.cfg`（Windows は `%APPDATA%/Godot/app_userdata/NPBオーペナゲーム/settings.cfg`）の `[voice]` を書き換える。

```ini
[voice]
enabled=true
volume=80
backend="os"            ; os / voicevox / wav
rate=1.0                ; 話す速さ
voicevox_url="http://127.0.0.1:50021"
voicevox_speaker=3
wav_dir="user://voice"  ; 絶対パスでもよい（例 "C:/Users/<名前>/Documents/draft_voice"）
```

1. `os`（初期値）：Windows の日本語の声（`DisplayServer.tts_speak`）。日本語の声が入っていないと読み上げなし
2. `voicevox`：VOICEVOX 互換のエンジン（VOICEVOX・COEIROINK など）を自分で起動しておく。`/audio_query` → `/synthesis` で合成して再生。
   つながらない・失敗したときは、その起動の間は 1 で読む
3. `wav`：`wav_dir` に部品ごとの録音（16bit の WAV）を置くと、それをつないで再生し、無い部品だけ 1 で読む。ファイル名（`.wav` の前）は
   - 決まり文句：`round_1`〜`round_10`（第N巡選択希望選手）、`ikusei_round_1`〜（育成選手、第N巡選択希望選手）
   - 球団：`team_<略称>`（`team_巨人`・`team_ロッテ`・`team_DeNA` など。略称は GameData.TEAM_SHORT）
   - 守備位置：`pos_投手`・`pos_捕手`・`pos_内野手`・`pos_外野手`
   - 選手名・出身校（任意）：`name_<名前（空白なし）>`・`school_<出身校>`（出身校は `school_法政大学` が無ければ `school_法政大` も探す）

OS の音声合成は**終わり際に止めない**（docs/AUTORUN.md 作業42）。Godot 4.7 の Windows（OneCore）は、読み終えた瞬間に別のスレッドで
MediaPlayer を閉じるので、同じときに `tts_stop()` を呼ぶとゲームごと固まる（発表を読み終えたところで「次へ」を押すとフリーズした）。
`DraftVoice` は読み始めてからの時間と長さの見込み（1文字0.08秒）を比べ、残りが0.8秒を切っていれば止めずに自然に終わらせ、
終わるまで次の OS の読み上げを始めない（終わりの合図が来なければ5秒であきらめる）。テストは `tts_sim`（音を出さないまね）で確かめる

名前の読み：候補に `kana`・`yomi` があればそれを読む。無ければ `user://voice/readings.json`（`{"宗山 塁": "むねやまるい"}` の形、任意）、それも無ければ漢字のまま。
実在のアナウンサーの声をまねて学習させることはしない（本人の同意が無いため）。

## 所属の管理と年越し（`LeagueRoster`、docs/SPEC.md「決定事項：所属の管理と史実の出来事」）

誰がどの球団にいるかは `GameState.league.team_of`（選手ID → 球団）で持ち、年が変わっても引き継ぐ。
能力値ファイルは能力の値を引くためだけに使い、読み込むたびに `GameData.apply_roster()` で所属を上書きする
（`GameData.players_of()`・`teams()`・選手データの `team` はゲーム内の所属。史実の球団は `hist_team`。所属していない選手は `team` が空）。
`Season` は `GameData.rostered_players()` から作る。

- 開始時：開幕時点の能力値ファイルの球団。ただしその年の開幕後に史実でトレードされた選手は移籍前の球団から（能力値ファイルは1年分の在籍なので移籍後の球団になっていることがある）
- シーズン中：史実のトレード（`data/trades.json`）を日付どおりに毎日起こす（CPU球団どうしで、全員がまだ移籍元にいるときだけ。自球団が関わるものは起きない）。`Season.transfer()` で両球団の1軍を自動で組み直す
- オフ（`GameState._enter()`）：
  - FA・トレード・ポスティング：メジャー移籍（`data/mlb_moves.json` の `left_after` の年。自球団の選手もいったん退団し、画面で引き留めを試せる）、年内のトレード、
    来季の準備（来季の開幕時点のファイルを `peek_ratings()` で先読みし、引退・仮IDの付け替え・メジャーからの復帰・新加入・外国人市場の候補を決める）、メジャーからの復帰（史実の球団へ）、
    FA宣言（`league.open_fa()`）。締め切り（`GameState.fa_resolve()`。可変ボタンで次へ進むときも自動）で移籍先が決まる
  - 契約更改：全選手の年俸を査定してすぐ反映（`league.renew_contracts()` → `Salary.renew`）。自球団は画面で調整（下記「契約更改」）
  - 戦力外・引退：来季のファイルにいない選手は引退（外国人は「退団」と記録）。続けて支配下の上限で戦力外（下記「戦力外・引退」）
  - ドラフト：新人（前年秋のドラフトで指名された選手）とその他の新加入を史実の球団へ（ドラフト画面ができたら差し替える）
  - 春季キャンプ：新しい年のファイルを読み、仮ID（`tmp:…`、1軍に出ていない選手）を本来のIDに付け替え、球団名の変更（横浜→DeNA、自球団も）
  - 開幕：開幕前日までのトレード、外国人市場を閉じる（残った候補は来日しない）
- 外国人市場：来季に来日する新外国人（外国人の判定は `RosterRules.is_foreign`）。オフの間は新戦力の画面で自球団が獲得できる。
  CPU球団は契約更改・戦力外・ドラフトで1人ずつ、春季キャンプで残りを、史実で獲得した人数ぶん評価の高い順に獲得する。
  評価と提示額は来季のシーズン後の能力値に誤差（`MARKET_NOISE`）を足した「不完全な未来視」（画面に出す能力は開幕時点のまま）
- 記録：`league.log`（`kind`：trade / trade_skipped / mlb_leave / mlb_return / retire / rookie / join / foreign_candidate / foreign_sign / foreign_unsigned / rename /
  fa_declare / fa_move / fa_stay / mlb_keep / mlb_keep_failed）。新戦力の「出来事」タブに出す
- オフの編成：`GameState.sim_team_of(球団)`（`my_team()`）はオフの間、今の所属から自動で組んだ `SimTeam` を返す（所属が変わるたびに作り直す）

### FA・ポスティング（`FreeAgency`、docs/SPEC.md「決定事項：FA・ポスティング」）

- `GameState.fa()`（FA・トレード・ポスティングの段階だけ。それ以外は null）・`fa_open()`（締め切り前）・`fa_offer(id, 年俸, 年数)`・`fa_cancel(id)`・`mlb_keep(id, 年俸, 年数)`・`fa_resolve()`
- 締め切り前は可変ボタンが「FA・移籍交渉」でハブは FA の画面を開く（`GameState.advance()` は締め切ってから次へ進むので、テストや早送りでは画面を通さなくてよい）
- 国内FA：資格は在籍 `DOMESTIC_FA_YEARS`（8）年・前回から `REFA_YEARS`（4）年・複数年契約中でない・外国人枠でない。宣言は能力・出場量・年齢・年俸の安さからの確率
- 入札：CPU球団は必要度（同じ種類＝先発/救援/野手で何人目に入るか）と能力で決める（宣言したときに決め、締め切りまで非公開。画面には「関心：n球団」と、自球団の提示が通りそうかの★）。
  選手は 年俸×年数の上乗せ×元の球団の上乗せ×相性 の高い球団へ。入札が無ければ宣言残留。決まった年俸は契約年数のあいだ据え置き（`league.contract_until`。契約更改で飛ばす）
- 自球団の提示は希望額の 0.7〜2倍（`BID_CAP` 10億円まで）で、上限は予算の残り（`budget_room()`：予算上限−来季の総額の見込み−ほかの提示の上積み）まで。残りが下限より少なくても下限の額は出せる。
  CPU球団は予算上限を超える入札をしない（CPU球団の範囲は予算を考えない `base_range()`）
- メジャー移籍の引き留め：自球団の選手だけ1回。成功率 `MLB_KEEP_MIN`〜`MLB_KEEP_MAX`（5〜20%）。テストでは `fa.force_roll` で乱数を固定できる。
  成功したら `league.kept_mlb` に入り、`GameData.set_kept_players()`（`_sync_roster()` から）がその年のファイルの `mlb_players`（無ければ引き留めたときのNPBの能力値）を選手として足す（`kept_from_mlb`）。
  来季のファイルにいなくても引退させない（mlb_last の年まで）。史実でNPBに戻ったら普通の選手に戻る（`begin_year`）

### 年俸（`Salary`）

- 開幕時点（2008年）・途中加入：市場価値 `BASE × exp(K × 実力z) × 出場量^1.4`（実力z・出場量は能力値の直近3年の加重から）に
  在籍年数の係数（1年目0.3→7年目1.0→以降少しずつ上がり最大1.4）を掛け、在籍年数に応じた下限と比べる。3億円を超えた分は伸びを抑え、6.5億円で頭打ち
- 新人：ドラフト順位×高校／大学・社会人の表（1位 1500万／高校1200万 … 育成 400万／300万）
- 外国人：市場価値×1.3（最低3000万円）
- 契約更改：今季のゲーム内成績（OPS・防御率）と能力値から目標額を出し、減額制限（1億円超40%・以下25%）と上げ幅（3倍かつ+1.5億円まで）の範囲で近づける。
  今季がはっきり良い年（今季の実力z 0.5以上・出場量0.6以上）は少なくとも5%アップ、悪い年（z −0.5以下、年俸3000万円以上）は5%以上ダウン

### 契約更改（`ContractRenewal`）

- `GameState._enter(CONTRACT)` で `league.renew_contracts()` が全球団の全選手を査定し、来季の年俸として `league.salary` にすぐ入れる（CPU球団はこれで決まり）。
  自球団の選手は `league.contracts.rows`（今季・査定額・提示額・範囲・据え置きの理由）に入る。複数年契約中（FA・引き留め）とこのオフに加わった選手は据え置き
- `GameState.contracts()`（契約更改の段階だけ）・`contract_open()`（締める前）・`contract_set(id, 年俸)`（範囲に丸めて来季の年俸にすぐ反映）・`contract_resolve()`
- 提示できる範囲（`Salary.renew_limits`）：下限は減額制限（1億円超40%・以下25%）と査定額の90%の高いほう、上限は今季の3倍・+1.5億円の小さいほう（査定額より下にはしない）。保留（交渉決裂）は無し
- 締める前は可変ボタンが「契約更改」でハブは契約更改の画面を開く（`advance()` は締めてから次へ進む）
- 予算上限：`ContractRenewal.BUDGET`（巨人・ソフトバンク42億、阪神34億、中日32億、ロッテ・オリックス・横浜28億、西武・楽天・日本ハム27億、広島・ヤクルト24億）。
  総額は `league.next_payroll()`（このオフに引退する選手を除く）。契約更改そのものは予算で抑えない（超えた球団は球団別で赤）
- 2008年開幕の分布（`roster_year_check`）：平均 約3,300万円・中央値 約1,500万円・1億円以上 約60人・最高 約3.8億円、
  出場の多い選手の中央値 約9,000万円（下位1/4 5,500万・上位1/4 1.5億）、球団の総額 17〜35億円

### 戦力外・引退（`Releases`）

- `GameState._enter(RELEASE)` で史実の引退（`league.apply_retirements()`）のあと `league.open_releases()`：引退を `retired_rows` に並べ、
  CPU球団は来季の見込み（`league.registered_count()` 支配下＋`league.incoming()` 新人などの見込み）が `LeagueRoster.ROSTER_LIMIT`（70人）を超える分を
  `league.keep_score()`（能力＝`Salary.ability`・年齢・年俸）の低い順に戦力外にする（投手・野手それぞれ26人は残す）
- 支配下：育成選手（`league.is_ikusei()`：ドラフトが育成指名で、来季までに1軍に出ていない）は数えない。新人の見込みは史実の新人・新加入のうち支配下の人数
  （ドラフトの段階で入る）、CPU球団は外国人市場で獲る予定の残り（`cpu_demand`）も足す
- 戦力外にできない選手：複数年契約中・メジャー移籍を引き留めた・このオフに加わった（FA・復帰・外国人・戦力外からの獲得・トレード）
- `league.release_player()`：来季の能力値ファイルに同じIDでいれば市場（`market`、`market_info.released`＝元の球団、提示額は来季の見立ての70%）、いなければ引退。
  `league.released` に記録し、以後の年に新加入として戻ってこない。CPU球団は空きがあればドラフト・春季キャンプで評価の高い順に獲る（`cpu_release_round`、元の球団は獲らない）。
  開幕までに残った選手は引退（`release_unsigned`）。開幕でまだ70人を超えるCPU球団（年明けのトレードの人数差など）は超えた分を引退扱い（`trim_to_limit`）
- 自球団：`GameState.releases()`・`release_open()`・`release_toggle(id)`・`release_auto()`・`release_need()`・`release_resolve()`（足りなければ自動で選ぶ。可変ボタンで次へ進むときも自動）。
  締める前は可変ボタンが「戦力外・引退」で画面を開く。戦力外・引退の段階からは、自球団は支配下に空き（`GameState.user_room()`）が無いと市場の選手を獲れない。自分で戦力外にした選手は獲れない
- 新戦力の外国人市場に戦力外の選手も並ぶ（史実の球団の列に「戦力外（元の球団）」）。出来事に release / release_sign / release_unsigned / release_trim

## 成長・衰え・引退（`Growth`、docs/AUTORUN.md 作業27）

史実の能力値ファイル（`generated/ratings/<年>_pre|post.json`）が無い年（2028年の開幕から。2027年の開幕は `2027_pre.json`）は、
`Growth` で毎オフに能力を動かす。係数は `generated/growth.json`（`tools/growth_coefficients.py` が 2008〜2026年の開幕時点の
能力値の「1年での変化」から作る。中身は tools/README.md「growth_coefficients.py」）。単体の確認は `tests/growth_check.gd`。

**年越しへのつなぎ込み**（`sim/future_year.gd` の `FutureYear`、`GameState._prepare_future_year`）：来季が `Growth.FIRST_YEAR`（2028）以降なら、
オフの「FA・トレード・ポスティング」に入ったところで来季の開幕時点の能力値を1回だけ作り、`GameData.synthetic[来季]` に置く。
`GameData` はその年の `pre`・`post` の両方としてファイルより優先して使う（`find_ratings_path` は `synthetic:<年>`）ので、
LeagueRoster の来季の準備（来季にいない選手＝引退、球団なしの選手＝ドラフト候補・外国人市場）がそのまま動く。中身：
- 今の所属の選手：`should_retire`（今季のゲーム内の打席・アウト数で出場量を更新して判定。複数年契約の途中・メジャーから引き留めた選手は引退しない）、
  残った選手は `grow_league`（今季の打席・アウト数で出場量 `sample` も更新）。`team`・`hist_team` は今の所属
- 来季のファイルがあれば、その球団なしの選手（`tools/amateur_ratings.py carry` の 2028_pre の2027年の候補）を加える
- `GameState.future_newcomers`（Callable。来季の年, LeagueRoster → 選手の配列）が返す選手を加える（hist_team のある選手はその球団の新加入、空はドラフト候補。作業22・テスト用）
- 架空の外国人（下記「架空の外国人選手」）。CPU球団の欲しい人数は `LeagueRoster._fictional_demand`（来季も残る外国人が1球団7人に足りない分）
- 加えた選手は成長させない（fresh）。`foreign_target`・`foreign_pitcher_share`・`growth_note`（引退・外国人・候補の人数）も入る
- セーブ：`GameState.to_save()` の `synthetic`（今年と来季の分）。ロードで `GameData.synthetic` に戻してから能力値を読む
- 日程・名簿の無い年（`GameData.SCHEDULE_COPY_FROM` の2026年より後）：日程はいちばん近い前の年の日程を同じ曜日のまま写す（`copy_schedule`）、
  1軍初出場の年はいちばん近い前の年の名簿＋ゲーム内で入った年（`GameData.debut_extra`＝`LeagueRoster.joined`）
- 確認は `tests/future_year_check.gd`（2027年開始で数年。ドラフトの候補が無い年は `future_newcomers` で史実の新人をひな形に補充）

- `Growth.new()`（係数を読む）→ `grow_league(選手の配列, 来季の年, rng, fresh, seasons)`：全員を来季の開幕時点の能力にした新しい配列を返す（入力は変えない）。
  `fresh`（選手ID → true）は今オフに入ったばかりの選手（新人など）で、成長させず平均の計算にだけ入れる。
  `seasons`（選手ID → `{pa_1, pa_2, outs_1, outs_2, bonus}`）は今季のゲーム内の成績で、出場量（`sample`）の更新と好成績の後押し（`bonus`：項目 → 点数、最大±3）に使う
- 1人分は `grow(選手, 来季の年, rng, season)`。年齢は来季の4月1日時点の満年齢（`Growth.age_at`）
- 実在の選手：能力の項目ごとに `今の値 + a(年齢) + b(年齢)×(今の値−63) + sd(年齢)×ゆらぎ`。ゆらぎは史実の残差の分位点（裾が重い＝急成長・急な衰え）で、
  項目どうしは史実の残差の相関でつながる。入団して最初の1回だけは出場の少ない選手（新人）の係数を混ぜる（2回目からは出場の多い選手の係数。ゲームは2軍の試合をしないため）
  - 投手の役割（先発・救援）は史実の移り変わりの確率で変わり、スタミナは移り変わりの種類ごとの係数で動く（先発はスタミナ 62.5 以上、救援は未満に揃える）。
    総合は役割ごとに K/9・BB/9・HR/9 の値からの式＋選手ごとのずれ（総合は FIP から出した値なので、内訳と一緒に動かす）
  - 野手の守備力・肩力は主な位置の変化を全部の守備位置に同じだけ足す。弾道はパワーの段が変わった分だけ動く。球速は km/h（120〜168）
  - 守備の記録が無い新人の野手（`fielding` が空、`primary_pos` が「内野手」など）は、最初の成長で史実の新人の2年目の守備位置・守備力の例から1つ選んで付ける
  - 特殊能力（`abilities`）・成績の内訳（`detail`）は変えない。成長させた選手には `growth_year`（その能力の年）が付く
- リーグ全体：成長のあと、項目ごとの平均・ばらつき（スタミナは役割ごと）と先発の割合を、史実の直近10年の開幕時点（`target`）へ半分ずつ寄せる。
  目安は史実のファイルの全選手（育成を含め1,000〜1,200人）なので、ゲームの選手がそれより少ないと所属選手の平均は少しずつ下がる（年越しの確認で10年でミート −3 ほど）
  2027年から10年進めても平均・上位の人数・先発の人数・試合の成績（打率・防御率）がほぼ変わらないことを確認済み（growth_check・future_year_check）
- 引退：`retire_probability(選手, 来季の年, 外国人か, 出場量)`（`should_retire` は乱数で判定）。史実（2008〜2026年）の「来季の名簿にいない」割合の
  ロジスティック回帰（年齢・実力 `Salary.ability`・出場量・外国人・投手、外国人は実力・出場との掛け算も）。国内の選手は 18〜23歳 1%・28〜30歳 11%・34〜36歳 25%・40歳〜 35%、
  外国人は 42%（1年目の実力の下位4分の1は 62%、上位4分の1は 18%）。
  戦力外で入団者のいない選手も含む割合なので、`Releases` の戦力外（支配下70人の上限）とはほぼ重ならない

### 架空の選手（作業22で使う項目）

架空の選手も能力値ファイルの選手と同じ形（`batting`・`pitching`・`fielding` など）で持ち、次の `growth` を足す。`growth` がある選手はピークへ向かって育つ。

```
"growth": {
  "type": "普通",            # 育ち方：「早熟」「普通」「晩成」
  "peak_age": 28,            # 任意。無ければ type から（早熟25・普通28・晩成31歳）
  "peak": {                  # 隠れたピークの値。野手は meet/power/eye/speed/defense/arm、投手は k9/bb9/hr9/stamina/velocity(km/h)/overall
    "meet": 78, "power": 70, ...
  }
}
```

- ピークの年齢までは毎年「(ピーク − 今の値) ÷ (ピークの年齢までの残り年数 + 1)」ずつ近づき、ゆらぎは史実の 0.6倍。`peak` に無い項目は実在の選手と同じ動き
- ピークの年齢を過ぎたら実在の選手と同じ仕組みで衰える（年齢を「28 − ピークの年齢」だけずらすので、早熟は早く衰え、晩成は遅い）
- 投手の役割は、スタミナがピークへ育つ間はスタミナで決まる（62.5 以上で先発）。総合を `peak` に入れない場合は K/9・BB/9・HR/9 から出す
- 守備位置は `fielding` に入れておく（空なら最初の成長で史実の新人の例から付く。その場合 `primary_pos` は「内野手」「外野手」「捕手」）
- 新人の1年目の能力（入団時の値）は作業22で決める（成長は翌オフから）。`sample` は `{"pa_1": 0, "pa_2": 0}` などでよい

## 架空の外国人選手（`ForeignPlayers`、docs/AUTORUN.md 作業31）

史実の無い年は、毎年の外国人市場に架空の外国人選手を出す（`FutureYear` が来季の能力値に球団なしで入れ、`LeagueRoster.prepare_next_year` が市場の候補にする）。
市場の一覧（新戦力）には本当の能力ではなく誤差を足した見立て（`market_info.scout`）のランクを出し、史実の球団の列は「架空（国）」。単体の確認は `tests/foreign_check.gd`。

- `ForeignPlayers.new()` → `generate_year(その年, rng)`：その年に来る候補の配列（能力値ファイルの選手と同じ形、`team` は空）。人数は史実の直近10年（2016〜2025年）のどれか1年の人数（28〜43人、投手が6割）
- 1人ずつ、史実の新外国人（2009〜2025年の599人）のひな形を1人選び、1年目の能力（その年のシーズン後の能力値）に小さなゆらぎ（能力値±3・球速±1km/h）を足す。
  当たり外れの大きさ・年齢（平均28.7歳）・守備位置・投打はひな形のまま。投手の総合は K/9・BB/9・HR/9 のゆらぎに合わせて動かす
- 出身（推定）は 米国 65%・中南米 30%（ドミニカ・ベネズエラ・メキシコ・プエルトリコ・パナマ・コロンビアに割り振る）・キューバ 3%・台湾 2%・韓国 1%。
  名前は出身に合わせて作る（「A.スミス」「J.ロドリゲス」、韓国・台湾は漢字の「姓 名」。同じ年に重ならない）。経歴は前の所属（メジャー球団1〜3・米マイナー・韓国・台湾の球団など）
- 選手データに `import`（`{country, prev, mlb_org, template_year}`）が付く。`draft` は空なので `RosterRules.is_foreign` は外国人と判定する。ID は `fgn:<年>:<番号>`
- 来日してからは `Growth` で育ち・衰える（新人の側の係数は使わない）。退団は `Growth.retire_probability`（外国人）
- `tests/foreign_check.gd`：2027年から10年、外国人の少ない球団から評価の高い順に獲ると、1球団の外国人は7.0人（史実7.1人）、1年で退団 52%（史実52%）、
  1年目の実力の上位4分の1は平均3.0年・下位4分の1は1.7年在籍（史実3.5年・1.7年）
- 年俸（提示額）は今の外国人市場と同じ `Salary.foreign_asking`（史実の年俸のデータは無い）

## 試合シミュレーション（`sim/`）

- 能力値は `z = (値 − 63) / 17`（`tools/README.md` のスケールの逆）に直し、各確率を「基準値のロジット＋係数×z」のシグモイドで出す
- 打席の流れ：死球 → 四球（選球眼×制球）→ 三振（ミート×奪三振）→ 本塁打（パワー・弾道×被弾抑制）→ 打球の質（ミート・パワー×総合力）→
  凡打球（内野の守備力でアウト/内野安打、アウトは失策判定、併殺）／鋭い当たり（外野の守備範囲で安打・長打を抑え、肩で進塁を阻止。範囲は守備力に走力を混ぜる：中堅 30%・左右翼 10%、`SimPlayer.range_at`。作業43）
- 走塁は走力と外野の肩で一塁→三塁・二塁→本塁・二塁打で一塁→本塁と憤死を判定。盗塁は走力で企図、走力と捕手の肩で成否
- 守備位置の慣れ（作業44、`SimPlayer.familiarity`）：能力値の detail の weight × 2.5（上限1）。守備力は「慣れ × 守備力 + (1−慣れ) × −2.5（一塁 −1.0）」（`defense_at`）。自動オーダー（`SimTeam._starter_score`）も試合もこれを使う
- 守備得点（`Records.fielding_runs`）は、機会ごとに「平均的な野手（z=0）と比べた成功の確率の差」（`GameSim._fld_exp`、〜d のキー）で数える（作業44。実際に捕れたかで数えると運のぶれが大きい）
- 試合に出るのは1軍（`SimTeam.active`）の選手だけ。代打は1軍の控えから
- 采配方針（`SimTeam.tactics`、−2〜+2。自球団は思考設定、CPUは0）：送りバントの頻度と対象、盗塁の企図率、先発を代える球数の目安が変わる（係数は `game_sim.gd` の `*_TACTIC_*`）
- 采配：投手の打順・打力の低い打者は無死一塁/二塁で送りバント、DHなしの終盤は投手に代打。先発は目安の球数（スタミナ）＋5球・5失点で交代、
  7〜9回の僅差リードはセットアッパー2人→抑えの順。リリーフは前日35球超・3連投になる日は休み
- 疲労：目安の球数を超えると15球ごとに z −0.45。先発は中5日以上あける6人ローテ
- 勝敗投手：最後に勝ち越したときの投手が勝利（先発は5回以上）、その走者の責任投手が敗戦。セーブ・ホールドは簡易判定

## セーブ／ロード（`SaveGame`、docs/AUTORUN.md 作業6）

- 保存先：`user://saves/`（Windows は `%APPDATA%/Godot/app_userdata/NPBオーペナゲーム/saves/`）の `slot1.json`〜`slot3.json`・`auto.json`（オートセーブ）。一覧表示用に `<枠>_info.json`（概要だけ）も書く。中身は `{version, slot, saved_at, summary, state}`（`VERSION`＝1）
- `state` は `GameState.to_save()`：年・日付・段階・自球団・成績・方針、`LeagueRoster.to_save()`（所属・年俸・推移・出来事・市場・引退・ドラフトの記録・仮の新人の選手データ・史実のトレードの進み具合・乱数、このオフの `FreeAgency`・`ContractRenewal`・`Releases`・`Draft` の途中経過）、`Season.to_save()`（全試合の日程と結果・球団成績・個人成績・乱数、各球団の `SimTeam.to_save()`＝顔ぶれ・1軍・オーダー・控え・ローテ・ブルペン・抹消日・登板間隔・方針）。選手などのオブジェクトは選手ID・球団名で持つ
- 能力値ファイルは保存しない。`GameState.load_state()` がその年・段階のファイル（シーズン中・春季キャンプは pre、オフは post。FA〜ドラフトは来季の pre も）を読み直し、`LeagueRoster.restore_plan()` で来季の準備の能力値の部分を作り直してから所属を当てる
- JSON にすると整数が小数になるので `SaveUtil.ints()` で戻す。乱数の状態（64ビット）は文字列で持つ。Dictionary のキーの並びも保つ（`sort_keys=false`）ので、ロード後に同じだけ進めると同じ結果になる（save_check で確認）
- オートセーブ：月替わり（`month_started`）とオフの段階の切り替わり（`_enter`）で印を付け、次のフレームの `GameState._process` で1回だけ書く（`skip_to_phase` の途中は書かない）。早送り中・自動処理の途中は手動のセーブができない（`GameState.can_save()`／`save_block_reason()`）
- テスト（`-s` でスクリプトを実行）のときは `user://test_saves/` を使い、オートセーブは既定で書かない（`SaveGame.autosave_enabled`）
- 6月中旬のセーブで約2MB・保存0.2秒・ロード1秒程度（シーズン終盤は全試合の結果の分だけ大きくなる）
